## 기본 경기 정보

### 주요 컬럼

| 컬럼 | 의미 |
| --- | --- |
| `season` | 시즌 연도 |
| `game_month` | 경기 월 |
| `game_dayofweek` | 경기 요일. 월요일=0, 일요일=6 |
| `inning` | 투구 직전 이닝 |
| `top_bottom` | 초/말 (`T`=초, `B`=말) |
| `game_type` | 경기 유형 코드 |

### 활용 아이디어

기본적으로 **Categorical 변수**로 활용할 수 있다.

#### `season`

투수의 능력이 시즌별로 달라질 가능성이 있기 때문에 단순 `pitcher_id`뿐 아니라

- 투수 × 시즌
- 팀 × 시즌

과 같은 조합도 검토할 수 있다.

예:

```
pitcher_season = pitcher_id + season
```

같은 투수라도 2022년과 2024년의 제구력이 동일하다고 보기 어렵기 때문이다.

#### `game_month`

월별로 시즌 초·중·후반을 어느 정도 구분할 수 있다.

가능한 가설:

- 시즌 초반 컨디션
- 여름철 체력 저하
- 시즌 후반 피로 누적

다만 실제 효과가 있는지는 반드시 데이터로 검증해야 한다.

#### `game_dayofweek`

요일 자체가 직접적으로 제구력에 영향을 준다고 단정하기는 어렵다.

대신 선발 로테이션, 경기 일정 등의 효과가 간접적으로 포함되어 있을 가능성이 있으므로 **우선 Feature로 유지한 뒤 중요도를 확인**하는 것이 적절해 보인다.

# 볼카운트

### 주요 컬럼

- `balls_before`
- `strikes_before`

투구 직전의 볼·스트라이크 카운트이다.

볼카운트는 투수가 **얼마나 공격적으로 혹은 어렵게 승부해야 하는 상황인지**를 나타내기 때문에 중요한 변수일 가능성이 높다.

### 야구적 가설

예를 들어:

- **0-0** : 초구 스트라이크를 잡으려는 경향
- **0-2** : 투수가 유리하기 때문에 존에서 벗어나는 유인구를 사용할 여유가 있음
- **3-0** : 볼넷을 막기 위해 스트라이크를 넣어야 하는 압박이 강함
- **3-2** : 볼넷과 삼진이 동시에 걸려 있기 때문에 제구 중요도가 매우 높음

즉,

```
balls_before + strikes_before
```

만 보는 것보다 **각 카운트 조합 자체가 서로 다른 상황**이다.

### Feature Engineering 후보

```
count_state
0-0
0-1
0-2
1-0
1-1
1-2
2-0
2-1
2-2
3-0
3-1
3-2
```

추가로:

- `pitcher_ahead` : 투수가 유리한 카운트
- `batter_ahead` : 타자가 유리한 카운트
- `full_count`
- `two_strike`
- `three_ball`

등을 만들 수 있다.

# 아웃카운트

### 컬럼

`outs_before`

투구 직전 아웃카운트이다.

단순한 0/1/2 아웃 정보뿐 아니라 **주자 상황과 결합했을 때 의미가 커질 가능성**이 있다.

예:

```
1아웃 + 1루
```

에서는 병살타가 가능한 상황이기 때문에 투수가 땅볼을 유도하는 승부를 선택할 가능성이 있다.

따라서 `outs_before` 하나보다는

```
outs_before × base_state
```

조합을 보는 것이 더 의미 있을 수 있다.

# 점수 및 점수차

### 주요 컬럼

| 컬럼 | 의미 |
| --- | --- |
| `run_top_before` | 투구 직전 초 공격 팀 점수 |
| `run_bot_before` | 투구 직전 말 공격 팀 점수 |
| `run_total_before` | 양 팀 합산 점수 |
| `score_diff_home` | 홈 팀 기준 점수 차 |
| `score_diff_pitcher_team` | 투수 팀 기준 점수 차 |

### 활용 아이디어

점수차는 투수의 **심리적 압박과 투구 전략**에 영향을 줄 수 있다.

예:

```
9회 1점 차
```

와

```
3회 10점 차
```

는 같은 한 번의 투구라도 상황의 중요도가 크게 다르다.

점수차가 크게 벌어진 경우에는 투수가 상대적으로 공격적으로 승부할 가능성이 있고, 접전에서는 제구에 대한 부담이 증가할 가능성이 있다.

### Feature Engineering 후보

```
abs_score_diff
pitcher_team_leading
pitcher_team_trailing
tie_game
close_game
blowout_game
```

예를 들어:

- `close_game = |score_diff_pitcher_team| <= 2`
- `blowout_game = |score_diff_pitcher_team| >= 5`

등의 방식이다.

특히

```
inning × score_diff
```

조합이 중요할 수 있다.

같은 1점 차라도 2회와 9회는 상황의 중요도가 완전히 다르기 때문이다.

# 주자 상황

### 주요 컬럼

| 컬럼 | 의미 |
| --- | --- |
| `runner_on_1b` | 1루 주자 존재 여부 |
| `runner_on_2b` | 2루 주자 존재 여부 |
| `runner_on_3b` | 3루 주자 존재 여부 |
| `num_runners_on` | 출루 주자 수 |
| `base_state` | 전체 주자 상황 |

`base_state` 예시:

- 주자 없음
- 1루
- 2루
- 3루
- 1·2루
- 1·3루
- 2·3루
- 만루

### 활용 아이디어

주자 상황은 단순한 심리적 압박뿐 아니라 **투구 전략 자체를 바꾸는 요소**일 수 있다.

대표적으로:

### 1아웃 + 1루

병살타가 가능한 상황이다.

따라서 투수가 땅볼을 유도할 수 있는 코스 또는 구종을 선택할 가능성이 있다.

예시 가설:

- 우투수 vs 우타자 → 몸쪽 낮은 코스 활용 가능성
- 우투수 vs 좌타자 → 바깥쪽 낮은 코스 또는 떨어지는 변화구 활용 가능성

중요한 점은 **현재 투구의 실제 구종이나 실제 목표 코스를 미리 알 수는 없기 때문에**, 이런 전략을 직접 넣는 것이 아니라 투구 직전 상황을 이용해 그 전략이 나올 확률을 간접적으로 Feature화**해야 한다는 것이다.

### 중복성

`runner_on_1b`, `runner_on_2b`, `runner_on_3b`, `num_runners_on`, `base_state`는 상당한 정보 중복이 있다.

하지만 트리 모델에서는 중복 변수가 반드시 치명적인 것은 아니다.

따라서 처음부터 무조건 삭제하기보다는

1. 모두 사용한 모델
2. `base_state`만 사용
3. 개별 runner 컬럼만 사용

등을 비교해 Validation 성능으로 판단하는 것이 좋다.

# 기대 승률

### 주요 컬럼

- `home_win_expectancy`
- `away_win_expectancy`

투구 직전 경기 상황에서 각각 홈/원정 팀의 기대 승률이며 범위는 0~100이다.

### 해석

단순히 경기 결과를 예상하는 정보가 아니라 **현재 경기 상황이 얼마나 한쪽으로 기울어져 있는지를 압축해서 나타내는 변수**로 볼 수 있다.

특히 경기 후반에는 의미가 커질 가능성이 있다.

예:

```
9회 1점 차
```

에서는 기대 승률 변화가 크지만,

```
2회 1점 차
```

에서는 상대적으로 영향이 작을 수 있다.

따라서 기대 승률을 제거하기보다는 다음과 같은 interaction을 실험할 가치가 있다.

```
inning × win_expectancy
inning × score_diff
```

# Leverage Index (`Li`)

`Li`는 해당 상황의 **경기 중요도**를 나타내는 변수이다.

값이 높을수록 현재 플레이가 경기 결과에 미치는 영향이 큰 상황이다.

### 활용 아이디어

`Li`는 투수가 느끼는 압박 상황을 나타내는 대리 변수로 사용할 수 있다.

예:

```
Li 낮음
→ 비교적 부담이 적은 상황

Li 높음
→ 중요한 승부 상황
```

따라서

```
Li × pitcher_id
Li × inning
Li × score_diff
Li × base_state
```

등의 interaction도 후보가 될 수 있다.

특히 **압박 상황에서 제구력이 크게 떨어지는 투수와 그렇지 않은 투수**가 존재한다면 유용할 가능성이 있다.

### `Li` (Leverage Index)

`Li`는 현재 상황이 경기 결과에 얼마나 큰 영향을 미치는지를 나타내는 값으로, **값이 높을수록 중요한 경기 상황**을 의미한다.

단순히 `Li` 값 자체를 사용하는 것뿐만 아니라, **Li가 높아지는 상황을 구성하는 요소들을 함께 활용하는 아이디어**도 생각해볼 수 있다.

예를 들면:

- **이닝** → 경기 후반일수록 중요한 상황이 많을 수 있음
- **점수 차이** → 큰 점수 차보다 동점이나 1~2점 차 접전 상황이 중요할 수 있음
- **주자 상황** → 득점권 주자, 만루 등
- **아웃카운트** → 같은 주자 상황이라도 아웃카운트에 따라 중요도가 달라질 수 있음
- **초/말 상황** → 경기 후반에는 초/말 여부에 따라서도 상황의 중요도가 달라질 수 있음

따라서 `Li` 하나만 보는 것보다 **이닝 + 점수차 + 주자 + 아웃카운트 등의 경기 상황을 조합해서 활용하는 아이디어**가 있다.

또한 같은 높은 `Li` 상황이라도 투수마다 영향을 받는 정도가 다를 수 있다.

예를 들어:

> 평소에는 제구 성공률이 높은 투수인데 중요한 상황에서는 제구 성공률이 떨어지는가?
> 

또는

> 반대로 중요한 상황에서도 평소와 비슷한 제구력을 유지하는가?
> 

를 과거 데이터를 통해 확인해보는 방법도 생각할 수 있다.

즉, 단순히 “현재*상황이*중요한가?”만 보는 것이 아니라,

> **“이*투수가*과거에 중요한 상황에서 얼마나 제구를 잘했는가?”**
> 

를 Feature로 활용하는 아이디어이다.

등이 다르기 때문이다.

단순히 `pitcher_id`만 쓰는 것보다 **투수별 과거 제구 특성**을 같이 활용하는 것이 중요해 보인다.

```
좌투 vs 좌타
좌투 vs 우타
우투 vs 좌타
우투 vs 우타
```

Feature 예:

```
hand_matchup
```

투수가 동일해도 상대 타자의 타석 방향에 따라 투구 전략과 제구 난도가 달라질 가능성이 있다.

따라서

```
pitcher_id × batter_hand
```

또는

```
pitcher_hand × batter_hand
```

interaction이 유용할 수 있다.

# 11. `asof` 변수

`asof`는 **현재 투구가 이루어지기 직전까지 누적된 과거 정보**를 의미한다.

이번 문제에서 특히 중요한 Feature 그룹이다.

## 투수 전체 제구 이력

### `asof_pitcher_n`

현재 투구 이전까지 해당 투수에 대해 축적된 **표본 수**이다.

단순 rate보다 이 `n` 자체가 중요하다.

예를 들어:

```
투수 A
성공률 = 70%
n = 10

투수 B
성공률 = 70%
n = 1,000
```

이라면 동일한 70%라도 신뢰도가 완전히 다르다.

따라서 rate와 함께 반드시 `n`을 고려할 필요가 있다.

---

## 12. 투수 제구 방향 관련 누적 비율

### 주요 컬럼

- `asof_pitcher_success_rate`
- `asof_pitcher_reverse_rate`
- `asof_pitcher_middle_rate`

실제 데이터를 직접 확인해보면 단순히

```
스트라이크 = 성공
볼 = 실패
```

구조는 아니다.

예를 들어 실제 데이터에서는:

- 볼인데 Success로 분류되는 경우
- 스트라이크인데 Reverse로 분류되는 경우
- 한가운데 공이 Middle로 분류되는 경우

등이 존재한다.

따라서 이 변수들은 **스트라이크/볼 여부보다 투수가 의도한 제구 방향과 실제 투구 위치의 관계**를 반영하는 값으로 보는 것이 적절해 보인다.

### 활용 아이디어

각 rate를 그대로 넣는 것뿐 아니라:

```
success_rate - reverse_rate
success_rate - middle_rate
reverse_rate - middle_rate
```

같은 파생 변수도 실험할 수 있다.

또한 반드시 `asof_pitcher_n`과 같이 사용해야 한다.

# 투수 Ball / Strike Rate

### 주요 컬럼

- `asof_pitcher_ball_rate`
- `asof_pitcher_strike_rate`

해당 투수의 과거 투구 결과 경향을 보여준다.

주의할 점:

- `strike_rate`가 단순히 모든 비볼 결과를 의미한다고 가정하면 안 됨
- 파울 등의 처리 방식은 데이터 정의를 정확히 확인해야 함

제구 성공률과 스트라이크율은 같은 개념이 아니다.

예를 들어 원하는 코스에 정확하게 던진 공이 볼이 될 수도 있고, 가운데 몰린 실투가 스트라이크가 될 수도 있다.

따라서:

```
control_success 관련 변수
```

와

```
ball / strike 결과 관련 변수
```

를 분리해서 생각해야 한다.

최근 경기에서 **가운데 또는 위험 코스로 몰린 공의 비율**을 나타낸다.

즉 최근 실투 경향을 파악하는 데 사용할 수 있다.

예를 들어:

```
통산 middle_rate = 5%
최근 1경기 middle_rate = 15%
```

라면 최근 제구가 흔들리고 있다는 신호일 가능성이 있다.

### 파생 Feature 후보

```
recent_middle_1 - career_middle
recent_middle_3 - career_middle
recent_middle_5 - career_middle
```

# 16. 타자 기준 과거 정보

### `asof_batter_n`

현재 투구 이전까지 해당 타자가 상대한 전체 투구 표본 수이다.

특정 투수와의 상대전적이 아니라 **해당 타자가 지금까지 다른 투수들을 상대로 경험한 투구까지 포함한 누적 정보**이다.

### 주요 컬럼

- `asof_batter_success_rate`
- `asof_batter_middle_rate`

여기서 중요한 것은 이것이 **타자의 제구 능력**을 의미하는 것이 아니라,

> 해당 타자가 상대해 온 투수들이 그 타자를 상대로 어떤 제구 결과를 보였는가
> 

를 나타낸다는 점이다.

따라서 타자의 접근법이나 투수들의 상대 전략이 간접적으로 반영되어 있을 가능성이 있다.

예를 들어 어떤 타자에게 지속적으로 까다로운 코스로 승부한다면 해당 타자를 상대할 때 투수들의 제구 난도가 달라질 수 있다.

다만 이를 곧바로 '선구안'으로 해석하는 것은 조심해야 하며 실제 상관관계 확인이 필요하다.

# 17. 투수 구종 구성(Pitch Mix)

### 주요 컬럼

- `asof_pitcher_pitchmix_n`
- `asof_pitcher_fastball_rate`
- `asof_pitcher_breaking_rate`
- `asof_pitcher_offspeed_rate`

현재 투구 이전까지 해당 투수가 어떤 종류의 구종을 얼마나 사용했는지를 나타낸다.

예:

```
fastball 60%
breaking 30%
offspeed 10%
```

### 중요성

현재 투구의 실제 구종은 투구 전에 알 수 없지만, 과거 pitch mix를 통해

> "이 상황에서 어떤 계열의 공을 던질 가능성이 높은 투수인가?"
> 

를 간접적으로 추정할 수 있다.

그리고 구종마다 제구 난도가 다를 가능성이 있기 때문에 제구 성공 확률과 연결될 수 있다.

향후 가능하다면:

```
투수의 과거 구종 구성
×
볼카운트
×
타자 좌우
×
주자 상황
```

interaction을 고려할 수 있다.
